# Open Feelings — Agent Instructions

Project-specific guidance for any AI coding agent (Claude Code, Codex, Copilot, etc.). Shared agent behavior lives in `~/AGENTS.md`.

## Project shape

Open Feelings is a SwiftUI iOS 26.0 app (Swift 6.0) for naming and logging emotions. Local-first SwiftData store with optional private-CloudKit sync, optional Face ID / Touch ID / passcode lock, optional Apple Health "State of Mind" write, and optional local reminder notifications. No accounts, ads, analytics, or third-party SDKs. See `README.md`, `ATTRIBUTION.md`, and `DATA-LICENSE.md` for license/attribution detail.

## Build, run, test

The Xcode project is generated by **XcodeGen** from `project.yml`. Regenerate after adding, removing, or renaming source files; otherwise `project.pbxproj` will be stale and new files won't be in the build.

```sh
# Regenerate the Xcode project (required after file moves)
xcodegen generate

# Simulator build (no signing)
xcodebuild -project OpenFeelings.xcodeproj -scheme OpenFeelings \
  -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build

# Full test suite on iPad simulator (matches what current-state.md verifies)
xcodebuild -project OpenFeelings.xcodeproj -scheme OpenFeelings \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPad (A16),OS=26.0.1' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO test

# Single test (XCTest -only-testing syntax: TestTarget/TestClass[/testMethod])
xcodebuild ... test -only-testing:OpenFeelingsTests/WheelViewportTransformTests

# Signed device build (uses dev.finklea.openfeelings provisioning profile)
xcodebuild -project OpenFeelings.xcodeproj -scheme OpenFeelings \
  -destination generic/platform=iOS -derivedDataPath DerivedData build
```

Tests use **XCTest** (not Swift Testing) and live in `OpenFeelingsTests/`.

## Architecture invariants

Three things span multiple files and are easy to break.

### 1. Persisted log vs. static taxonomy

`FeelingLog` (`OpenFeelings/Models/FeelingLog.swift`) is the only `@Model` and stores emotion picks as **string ID + display name pairs** at three levels (core / secondary / specific). It does **not** reference the taxonomy structs directly, so the static taxonomy in `EmotionTaxonomy.swift` can evolve without breaking historical logs.

To reconstitute a full selection from a log, call `EmotionTaxonomy.selection(coreID:secondaryID:specificID:)`. Educational copy shown when a feeling is selected lives in `EmotionDefinitions.swift` and is looked up via `EmotionSelection.definition` (most-specific available wins).

### 2. SwiftData store mode branches by environment

`OpenFeelingsApp.swift` builds the `ModelContainer` differently per runtime:

- **Tests** (`XCTestConfigurationFilePath` set) → in-memory store.
- **Simulator** → on-disk SwiftData store, **no** CloudKit. Unsigned simulator builds lack the CloudKit entitlement and will crash at startup if CloudKit is enabled — see `.docs/ai/decisions.md` (2026-04-28).
- **Device** → private CloudKit container `iCloud.dev.finklea.openfeelings`.

Don't unconditionally enable CloudKit; preserve the branching when touching the container setup.

### 3. The wheel viewport transform must stay invertible

`EmotionWheelView` applies pinch / two-finger rotate / drag-pan as a `WheelViewportTransform` (scale + rotation + offset) on top of a stable `EmotionWheelLayout`. Tap hit-testing inverts that transform to map screen taps back into layout space. `WheelViewportTransformTests` locks in `applied()` ∘ `inverted()` ≈ identity and the clamping rules — keep these green when changing gesture state, clamps, or transform math, otherwise selection silently drifts under zoom/rotation.

## Service injection

Services use two patterns; match the existing one when adding code:

- `HealthService` is `@MainActor @Observable`, instantiated once in `OpenFeelingsApp` and read via `@Environment(HealthService.self)`.
- `AppLockService`, `ReminderService`, `ExportService` are caseless `enum`s with static `async` methods, called directly from views.

All service entry points are explicit `async`/`await`; there are no callback APIs or DispatchQueue hops in app code.

## Repo specifics worth knowing

- Bundle ID: `dev.finklea.openfeelings`. CloudKit container ID matches.
- Entitlements (`OpenFeelings/OpenFeelings.entitlements`): HealthKit, CloudKit, APS development. `Info.plist` carries `NSFaceIDUsageDescription`, `NSHealthShareUsageDescription`, `NSHealthUpdateUsageDescription`.
- `DerivedData/` is git-ignored and used as the local derived-data path in the build commands above; safe to delete.
- Settings persist via `@AppStorage` (e.g. `appLockEnabled`, `healthEnabled`, `remindersEnabled`, `checkInMode`, reminder hour/minute).
- License split: Swift source is **MIT**; emotion taxonomy text is **CC BY-SA 4.0** (adapted from Open Emotion Wheel v1.1). See `ATTRIBUTION.md` and `DATA-LICENSE.md` before editing taxonomy strings.
